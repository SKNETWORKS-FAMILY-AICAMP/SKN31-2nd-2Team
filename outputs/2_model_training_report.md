# 산출물 2: 모델 학습 결과 보고서

## 1. 모델링 전략

### 1-1. 평가지표 선정

본 프로젝트는 Telco 고객 이탈(Churn) 예측 문제를 다룬다.  
이탈 고객을 놓치면 고객 유지 마케팅 기회를 잃을 수 있고, 비이탈 고객을 이탈 고객으로 잘못 예측하면 불필요한 마케팅 비용이 발생할 수 있다. 따라서 Accuracy만으로 모델을 평가하지 않고, 이탈 고객 탐지력과 예측 신뢰도를 함께 확인한다.

| 지표 | 선정 이유 |
| --------- | ------------------------------------ |
| Recall | 실제 이탈 고객을 놓치지 않는 것이 중요하기 때문에 우선적으로 고려 |
| Precision | 비이탈 고객을 이탈 고객으로 잘못 판단하는 경우를 관리하기 위해 필요 |
| F1-Score | Precision과 Recall의 균형 확인 |
| ROC-AUC | 전체적인 분류 구분력 확인 |
| PR-AUC | 불균형 데이터에서 Fraud 탐지 성능을 평가하는 데 적합 |
| Accuracy | 참고 지표로 활용 |

> Telco 고객 이탈(Churn) 예측에서는 False Negative, 즉 실제 Fraud 거래를 정상 거래로 판단하는 경우가 큰 손실로 이어질 수 있다.
> 따라서 Recall을 중요하게 보고, Precision과 PR-AUC를 함께 확인하였다.

### 4-4. 최적 모델 선정

**선정 모델**: LightGBM

**선정 근거**

1. 담당자별로 개별 모델 튜닝을 진행한 결과, 4-1의 전체 모델 성능 비교표에서는 GradientBoosting이 Accuracy 0.7555, ROC-AUC 0.8062로 가장 높은 성능을 보였다.
2. 하지만 동일한 조건에서 모델을 비교하기 위해 공통 전처리를 적용했을 때는 LightGBM이 가장 우수한 결과를 보였다. 이는 모델 자체의 성능을 비교할 때 전처리 차이에 따른 영향을 줄이고, 동일한 기준에서 평가했다는 점에서 중요한 판단 근거가 된다.
3. GradientBoosting과 LightGBM의 성능 차이는 매우 크지 않다고 판단하였다. 특히 본 프로젝트에서 중요하게 본 ROC-AUC 기준으로 두 모델의 차이가 작기 때문에, 단순히 개별 튜닝 결과의 1위 모델을 선택하기보다는 공통 전처리 기준에서 가장 좋은 결과를 보인 모델을 최종 모델로 선정하는 것이 더 타당하다고 보았다.
4. 따라서 최종 모델은 LightGBM으로 선정하였다. LightGBM은 ROC-AUC 기준으로 안정적인 분류 구분력을 보였으며, 학습 속도와 운영 효율성, Feature Importance를 통한 해석 가능성 측면에서도 고객 이탈 예측 모델로 활용하기 적합하다.

### 4-6. 최적 임계값 결정

최종 모델 선정은 임계값에 영향을 받지 않고 전체적인 분류 구분력을 평가할 수 있는 ROC-AUC를 기준으로 진행하였다. 다만 실제 서비스에서는 모델이 산출한 이탈 확률을 이탈/비이탈 클래스로 변환해야 하므로 Threshold 설정이 필요하다.

현재 단계에서는 별도의 Threshold 탐색 결과가 확정되지 않았기 때문에 기본 Threshold인 0.50을 적용하였다. 즉, LightGBM이 예측한 이탈 확률이 0.50 이상이면 이탈 고객으로 분류하고, 0.50 미만이면 비이탈 고객으로 분류한다.

| 항목 | 값 |
| --- | --- |
| 기본 Threshold | 0.50 |
| 최종 적용 Threshold | 0.50 |
| 모델 선정 기준 지표 | ROC-AUC |
| Threshold 적용 목적 | 예측 확률을 이탈/비이탈 클래스로 변환 |

---

### 4-7. Threshold Trade-off 분석

Threshold는 이탈 고객을 얼마나 적극적으로 탐지할 것인지 결정하는 기준이다. Threshold를 낮추면 이탈 가능성이 조금만 높아도 이탈 고객으로 분류하므로 Recall은 증가하지만, 실제로는 이탈하지 않을 고객까지 이탈 고객으로 판단하는 오탐이 늘어날 수 있다. 반대로 Threshold를 높이면 더 확실한 고객만 이탈 고객으로 분류하므로 Precision은 증가하지만, 실제 이탈 고객을 놓칠 가능성이 커진다.

본 프로젝트에서는 고객 이탈 방지 마케팅에 활용하는 것을 목표로 하므로, 실제 운영 단계에서는 기본값 0.50을 기준으로 시작하되 마케팅 비용과 이탈 고객 미탐 비용을 함께 고려하여 Threshold를 조정할 필요가 있다.

| Threshold 변화 | 영향 |
| --- | --- |
| 낮게 설정 | Recall 증가, 실제 이탈 고객을 놓칠 가능성 감소, 비이탈 고객을 이탈로 잘못 판단하는 오탐 증가 가능 |
| 높게 설정 | Precision 증가, 오탐 감소, 실제 이탈 고객을 놓칠 가능성 증가 |
| 0.50 유지 | 일반적인 기본 분류 기준으로 안정적인 비교 가능, 운영 목적에 따라 추가 조정 필요 |

| 주요 Feature 후보 | 해석 방향 |
| --- | --- |
| `MonthlyCharges` | 월 요금이 높을수록 비용 부담이 커질 수 있으며, 이탈 가능성 증가 요인으로 작용할 수 있음 |
| `Tenure` | 가입 기간이 짧은 고객은 서비스에 대한 고착도가 낮아 이탈 위험이 높을 수 있고, 장기 고객은 상대적으로 유지 가능성이 높을 수 있음 |
| `TotalCharges` | 누적 청구 금액은 고객의 이용 이력과 규모를 나타내며, 가입 기간 및 월 요금과 함께 고객 유지 패턴을 설명 |
| `Age` | 연령에 따라 서비스 이용 목적, 요금 민감도, 계약 선호도가 달라질 수 있음 |
| `Contract` | 월 단위 계약과 장기 계약 간 이탈 위험 차이를 파악하는 데 활용 가능 |
| `PaymentMethod` | 결제 방식에 따라 고객의 서비스 이용 편의성이나 결제 안정성 차이가 나타날 수 있음 |

### 5-3. 고위험 고객 프로파일

최종 모델의 주요 변수 해석을 바탕으로, 이탈 가능성이 높은 고객군은 다음과 같이 정리할 수 있다. 이 프로파일은 실제 마케팅 대상 고객을 선별하거나, 이탈 방지 캠페인의 우선순위를 정하는 데 활용할 수 있다.

* 월 청구 금액이 높아 비용 부담이 큰 고객
* 가입 기간이 짧아 서비스 이용 안정성이 아직 낮은 고객
* 누적 청구 금액이 낮거나 이용 이력이 충분히 쌓이지 않은 고객
* 월 단위 계약 등 해지 전환이 쉬운 계약 유형에 속한 고객
* 특정 결제 방식 사용으로 결제 편의성이나 서비스 만족도가 낮을 가능성이 있는 고객
* LightGBM 모델이 산출한 이탈 예측 확률이 0.50 이상인 고객

## 6. 결론

본 보고서에서는 Telco 고객 이탈 예측을 위해 여러 후보 모델을 학습하고, 모델별 성능을 비교하였다. 이탈 고객 예측에서는 단순 정확도보다 실제 이탈 가능성이 높은 고객과 낮은 고객을 얼마나 잘 구분하는지가 중요하므로, 최종 모델 선정 시 ROC-AUC를 핵심 평가지표로 활용하였다.

최종 모델은 LightGBM으로 선정하였다. LightGBM은 검증 데이터 기준 ROC-AUC 0.8055를 기록하여 후보 모델 중 상위권의 분류 구분력을 보였으며, Accuracy, Precision, Recall, F1-Score에서도 전반적으로 균형 잡힌 성능을 나타냈다. 특히 GradientBoosting과의 ROC-AUC 차이가 매우 작아 예측 성능 측면에서 경쟁력이 충분했고, 학습 속도와 대용량 데이터 처리 효율성, Feature Importance를 통한 해석 가능성까지 고려했을 때 실제 운영 환경에 적용하기 적합한 모델로 판단하였다.

따라서 본 프로젝트에서는 고객별 이탈 확률을 산출하고, ROC-AUC 기반으로 안정적인 분류 성능을 보이는 LightGBM을 최종 이탈 예측 모델로 사용한다. 향후에는 예측 확률에 대한 Threshold를 조정하여 Recall과 Precision의 균형을 세밀하게 조절하고, 주요 변수 중요도를 활용해 고위험 고객군의 특성을 해석함으로써 이탈 방지 전략 수립에 활용할 수 있다.
